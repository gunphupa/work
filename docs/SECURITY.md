# Security and privacy implementation

- No public secret variables, key-entry UI, raw provider logs, HTML rendering of model text, arbitrary fetch proxy or URL-fetch endpoint. React escapes user/model/source text. External links are reviewed catalogue URLs or clearly labelled marketplace searches with encoded query strings.
- API routes have `Cache-Control: no-store`; client bundles and self-hosted Thai fonts contain no credentials. CSP blocks external scripts and framing; production scripts are self-only. HSTS/TLS belongs on the public reverse proxy.
- HttpOnly, SameSite=Strict guest cookies; Secure when public origin uses HTTPS. CSRF token required in a header, exact configured Origin required. Sessions expire after 24 hours and are removed with old quota rows during later requests. IPs are stored only as keyed hashes; session creation is IP-limited.
- No request text, photos or provider response bodies in logs. AI logs contain only outcome, mode, status and latency. Logs intentionally omit provider errors that might contain user content.
- Browser input: up to five JPEG/PNG/WebP files, each ≤10 MB and ≤40 MP. Browser decoding resizes to longest edge 1600px, re-encodes WebP, strips metadata and rejects results above 2 MB. Server body cap: 15 MB; base64 characters and byte length validated; Sharp checks actual format, pages and ≤16 MP decoded size, then re-encodes. MIME spoofing and invalid bytes are rejected. Files are not written to disk.
- Before image transmission, the user must explicitly consent. Input images exist temporarily in the browser and processing buffers. There is no persistent result-photo feature in this release. Deleting local data does not delete provider-side records; no provider retention/training guarantee is made.
- Text plus inventory context is capped at 50,000 characters; specification maps are bounded to 12 fields per item. All AI modes use the same quota gate. Defaults: 50 global/day, 10/session/day, 15/hashed-IP/day, 3/hashed-IP/minute, 2 concurrent, 30s request timeout, 0 automatic retries. Reservations count failures. These are request caps, not exact monetary limits; set provider-side budget controls too.
- Do not trust arbitrary `X-Forwarded-For`. Set `TRUST_PROXY` only to a verified upstream proxy range/topology; an incorrect setting can weaken abuse protection. Without proxy trust, shared ingress IPs share the quota. Public deployment should add ingress request limits and appropriate bot protection. Anonymous cookies alone are not treated as robust abuse protection.
- Quotas need persistent SQLite and one Node instance. Do not run multiple ephemeral replicas with separate counters. A distributed version would need atomic shared storage.
- `REBUILD_AI_KEY` is absent during current validation. Live prompt-injection resilience and image recognition quality remain unmeasured. Untrusted output can still be wrong; it is never authority for readiness or changes to inventory.
